# UX_IDEAS — Rezerwo · улучшение клиентского опыта

> **Ветка:** `feature/ux-improvements`
> **Цель:** довести опыт клиента (того, кто записывается) до уровня, когда запись —
> это 30 секунд без трения, а салон возвращает клиента сам.
> Владельца почти не трогаем — только там, где нужен backend под клиентскую фичу.

---

## Как пользоваться этим файлом

Каждый этап самодостаточен. Промпт агенту:

```
Реализуй Этап UX-1 из UX_IDEAS.md. Не трогай готовые модули.
После — cd frontend && npm run build, почини типы, покажи диф.
```

**Обязательные правила (из CLAUDE.md):**
- Все новые строки UI — сразу в 4 языка: `pl.ts` → `en.ts` → `ru.ts` → `ua.ts`. TS не соберётся, пока не заполнены все.
- Никакого хардкода польского текста в TSX (кроме `AdminPage` и юр-страниц).
- Каждый новый backend-роут для владельца — owner-scoped через `owner_id`.
- Клиентские роуты (`/api/public/...`) — без авторизации, но с rate limiting и валидацией ввода.
- Деньги — число, время — `start_min` (минуты от 00:00), даты — строка `YYYY-MM-DD`, зона `Europe/Warsaw`.
- `npm run build` зелёный перед каждым коммитом. Коммит: `feat:` / `fix:` + `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`.
- Стили — инлайн `style={S.xxx}`, иконки — только `lucide-react`.

**Легенда объёма:** `S` ≈ пара часов · `M` ≈ день · `L` ≈ несколько дней.

## Этап UX-2 — Флоу бронирования

Ядро продукта. Сделать так, чтобы клиент не блуждал «день → нет слотов → назад».

- [ ] **2.1 · Доступность прямо в выборе даты (M)**
  - Что: при входе на шаг `date` — параллельно запросить слоты на 14 дней (или новый лёгкий
    эндпоинт `GET /public/businesses/:slug/availability?service_id=&master_id=&days=14`,
    возвращает `{ "2026-09-08": 6, "2026-09-09": 0, ... }` — счётчик свободных окон).
    Дни с `0` — приглушить и пометить «нет мест», не блокировать (вдруг освободится).
  - Зачем: сейчас тап по дню → шаг slots → «нет слотов» → назад. Много лишних шагов.
  - Где: `BusinessPage.tsx` `BookingWizard`, шаг `date` (`S.datePicker`); backend `server.js` рядом с `calcSlots`.
  - Backend: новый публичный роут, переиспользует `calcSlots` в цикле по датам. Кэш-заголовок ~60 сек.

- [ ] **2.2 · Чип «Ближайшее свободное» (S, после 2.1)**
  - Что: кнопка над date-picker → прыгает на первый день + первый слот с наличием, сразу шаг `details`.
  - Зачем: большинству клиентов всё равно когда — им нужно «побыстрее».
  - i18n: `t.earliestSlot`.

- [ ] **2.3 · Группировка слотов по времени суток (S)**

  - Зачем: при 20+ окнах сейчас сплошная стена кнопок (`S.slotGrid`).
  - Где: `BusinessPage.tsx:342`.
  - i18n: `t.morning`, `t.afternoon`, `t.evening`.

- [ ] **2.4 · Не пропускать выбор мастера при входе с услуги (S)**

    скипает выбор мастера, если клиент нажал «Zamów» у конкретной услуги.
  - Где: пересчитать стартовый шаг после загрузки `masters`.

- [ ] **2.5 · Крупная сводка перед подтверждением (S)**

  - Зачем: сейчас это одна мелкая строка `S.svcSummary`.
  - i18n: `t.paymentOnSite` (уже есть `p_priceOnSite` — переиспользовать).

- [ ] **2.6 · Раскрыть «подтверждение вручную» ДО брони (S)**

## Этап UX-3 — Управление записью клиентом (magic-link)

**Самый крупный пробел сейчас: клиент не может отменить/перенести запись — только звонком.**
Это бьёт по no-show и по нагрузке на владельца.

- [ ] **3.1 · Токен записи (M)**
  - БД: `appointments.manage_token TEXT` (генерить при создании, случайный 32+ символа).
    Идемпотентная миграция `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` в `initDb()`.
  - Backend: возвращать `manageToken` в `BookingResult`; НЕ отдавать в списках владельца/публичных.

- [ ] **3.2 · Публичная страница «Moja wizyta» (L)**
  - Роут фронта: `/wizyta/:token` (добавить в `App.tsx` роутер).
  - Backend: `GET /public/appointments/:token` → детали записи (салон, услуга, мастер, дата, время, статус).
    `POST /public/appointments/:token/cancel` → `status='cancelled'` (+ письмо владельцу).
    `POST /public/appointments/:token/reschedule` → проверка overlap через ту же логику слотов.
  - Rate limiting на эти роуты. Нельзя отменить запись, которая уже прошла / `done` / `cancelled`.
  - i18n: целый блок `t.myVisit*` (4 языка).

- [ ] **3.3 · Ссылка в письмах (S, после 3.2)**
  - Что: в `notifyClientBooking` и во всех reminder-письмах — кнопка «Zarządzaj wizytą» → `/wizyta/:token`.
  - Где: `backend/src/reminders.js` (шаблоны писем — не забыть `esc()`).
  - Зачем: отмена в один тап из напоминания резко снижает no-show.

- [ ] **3.4 · «Повторить запись» (S)**
  - Что: на странице `/wizyta/:token` и в письме после визита — кнопка «Записаться снова» →
    открывает `BookingWizard` c той же услугой и мастером.

**Backend UX-3:** новая колонка `manage_token`, 3 публичных роута, письма. Всё owner-scope не трогает
(клиентские роуты по токену).

## Этап UX-7 — Доступность и надёжность

Не фича, а гигиена. Можно делать параллельно с любым этапом.

- [ ] **7.1 · Семантика и ARIA (M)**
  - Карточки-ссылки (`<a>` вместо `<div onClick>`) — `MarketplacePage.tsx:371`, `:184` (лого).
  - `<label htmlFor>` ↔ `id` во всех формах бронирования/отзывов/waitlist.
  - `aria-label` на иконочные кнопки: крестик, «назад», точки фото, звёзды рейтинга.
  - `role="dialog"` + `aria-modal` на оверлеях.

- [ ] **7.2 · `prefers-reduced-motion` (S)**
  - В `index.css` — media-query, отключающий `rise`, `transition`, анимации прогресс-бара.

- [ ] **7.3 · Тосты вместо тихих ошибок (S)**
  - Общий компонент `Toast`. Сейчас часть ошибок сети в клиентских формах уходит в `.catch(()=>{})`.
  - (Владельцевая часть — `changeStatus`/`saveNote`/waitlist — уже покрыта, см. AUDIT M-3/4/5 ✅.)

- [ ] **7.4 · Фокус-видимость (S)**
  - `:focus-visible` стили для кнопок/полей/чипов (сейчас `outline:none` кое-где без замены).

- [ ] **7.5 · `<title>` и meta per-page (S)**
  - Менять `document.title` при навигации (`{Название салона} — Rezerwo`, `Поиск — Rezerwo`).
